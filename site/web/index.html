How it works

One request, start to finish.

The agent drives GPU for Agents through MCP tools (or the CLI with --json). The skill tells it to show you the price and ask before renting.

01

Ask

"Run this eval on Llama 8B." The agent writes jambu.yaml with gpu_init.

02

Price

gpu_offers lists matching GPUs under your cap. You say yes.

03

Serve

gpu_setup rents, boots vLLM and returns base_url, api_key, model. A stalled host is replaced.

04

Run, then stop

gpu_run runs the job. When requests stop, the watchdog stops the GPU.

Guardrails

Limits the agent can't talk its way past.

They live in jambu.yaml and on the machine. The agent can't raise them without editing the file, and the skill tells it to ask you first.

15 min

Idle timeout

No requests, no GPU. The watchdog on the instance stops it. lifecycle.idle_timeout

$/h

Hourly and session budget

Offers above the cap are never rented; a session that hits its total stops. budget.max_hourly_cost_usd

6 h

Maximum lifetime

A hard ceiling, busy or not. lifecycle.max_lifetime

10 min

Stalled hosts replaced

An image pull that stops moving gets a new host instead of a 30-minute wait. health.pull_stall_timeout

sweep

Last line of defense

gpu ls shows everything billing; gpu sweep --install-timer cleans up orphans.

jambu.yaml
gpu_runtime:
  provider: {name: vast}
  model_profile: qwythos-9b
  lifecycle:
    idle_timeout: 15m   # watchdog stops it
    max_lifetime: 6h
  budget:
    max_hourly_cost_usd: 0.60
    max_session_cost_usd: 5.00
  health:
    pull_stall_timeout: 10m
Install

Two commands.

Python 3.10+, a Vast.ai API key in .env or ~/.gpu/credentials. The agent never sees the key.

$ pipx install gpu4agents
$ cd your-project
$ echo "VAST_API_KEY=..." >> .env
$ gpu agent install # Claude Code
-t cursor-t desktop--global
# or drive it from any app, any language
$ gpu --json setup
{ "base_url": "https://…/v1",
  "api_key": "…", "model": "…" }
$ gpu run python eval.py
$ gpu destroy # or just walk away
